Obsidian_VN × Claude Code

Obsidian を司書にする

378 ファイルの Vault を、Claude が「必要なときだけ、必要な分だけ」自分で選んで読むようにする。 その作り方を、前提知識ゼロから順番に。

作るのはスクリプト 1 本とメモ 2 枚だけ。所要 30 分ほど。
ノートを 1 枚も書き換えずに済む方式で組みます。
まず結論

何を作るのか

Claude Code には「スキル」というしくみがあります。 スキル＝ Claude に渡しておくメモ書きだと思ってください。 「こういうときは、こうやって」と書いた Markdown ファイルを決まった場所に置くと、Claude がそれを読んで動く。

ここで作るのは、そのメモを 2 枚だけ 置く方法です。 メモの中身は「あなたのノートの一覧はこれ。この中から関係しそうなものを選んで読め」という指示。 Vault の中身は 1 文字も書き換えません。

ノートを 378 個スキルにするのではなく、
「378 個の目次を見せる係」を作る。

考え方

なぜ「全部スキルにする」ではダメなのか

Claude はセッションを開いた瞬間に、すべてのスキルの説明文（description）を暗記した状態で会話を始めます。 本文は読みません。読むのは「使う」と決めたときだけ。

つまり説明文は「常に持ち歩く荷物」です。ノートを 378 個スキルにすると、378 行の説明文を毎回カバンに入れて歩くことになる。 重いうえに、似た説明が並んで「どれだっけ」となり、選び間違いも増えます。

図書館でたとえると

Claude は司書、あなたのノートは本、Vault は書庫です。

ダメな方法
本 378 冊を全部カウンターに積んでおく。邪魔だし、探すのに時間がかかる。
やる方法
カウンターには 目次カード 1 枚だけ。司書はそれを見て、書庫から必要な 2〜3 冊だけ取りに行く。
しくみ

選別は 2 回に分かれている

ここが一番大事なところです。Claude は 2 段階でふるいにかけます。 1 回目は説明文だけを見て、そもそもノートを引くべき話かを判断する。 2 回目は目次を見て、どのノートを開くかを決める。

1 回目の判断材料は説明文だけなので、説明文の書き方が精度を決めます。 逆に言えば、チューニングする場所は 1 か所しかない。あとで効かないと感じたら、まずここを疑ってください。

設計

あなたの Vault をどう割るか

378 ファイルを 1 つの目次にすると、それだけで数千トークンになります。動きますが、もったいない。 幸い Obsidian_VN はもう用途ごとにフォルダが分かれているので、その線でスキルを分けます。 1 回目の選別がフォルダ単位になるぶん、目次も軽く、選別も当たりやすくなります。

Obsidian_VN/
├─ ClaudeArchive/vault-archive
│　├─ Chats/, Projects/
│　└─ _CrossMemory, _MOC_ClaudeArchive入口として重視
├─ VNworks/vault-works
│　└─ 68th全国握手会…, ブラザー様_大丸様…
├─ 個人用/最初は外す
├─ 対人メモ/最初は外す
└─ ルート直下の PDF / PNG後で足す

作るスキルは vault-works（案件）と vault-archive（過去の Claude 会話）の 2 枚。 性質がまるで違うので、説明文も自然に書き分けられます。

個人用 / 対人メモ を最初に外す理由

技術的な問題ではなく、切り分けの問題です。仕事の質問をしたときに人物メモが引っ張られてくると、 邪魔なうえに意図しない情報が会話に混ざります。まず仕事側で運用感をつかんで、 必要なら vault-personal を 3 枚目として足すのが安全です。

_MOC / _CrossMemory は消さずに載せる

アンダースコアで始まる目次ノート（MOC ＝ Map of Content）は、あなたが手で整理した最良の入口です。 自動生成の目次より質が高いので、除外せず、むしろ「まずここを見ろ」と手順に書きます。

実装

手を動かす

STEP 1

パソコン側の Vault の場所を突き止める

iPhone の Obsidian は iCloud 経由で同期していることがほとんどです。 その場合 Mac 側の実体は、ものすごく長いパスの奥にあります。まず居場所を確認します。

ターミナルMac
# iCloud 同期の Obsidian はここ
ls ~/Library/Mobile\ Documents/iCloud~md~obsidian/Documents/

# 見つからなければ、名前で探す（少し時間がかかる）
find ~ -maxdepth 6 -type d -name "Obsidian_VN" 2>/dev/null

出てきたパスを控えておいてください。以降 $VAULT と書いてある部分に入ります。

iCloud の「まだ降りてきてない」問題

iCloud はディスク節約のため、中身を実際にはダウンロードせず「見出しだけ」の状態でファイルを置くことがあります。 この状態のファイルは読もうとすると失敗します。

Finder で Vault フォルダを右クリック →「今すぐダウンロード」で全部降ろしておくのが確実です。 ふだんから Mac で Obsidian を開いているなら、たいてい降りています。

STEP 2

目次を作るスクリプトを置く

指定したフォルダの .md を全部さらって、「パス ＋ その中の最初の見出し」の一覧を出すだけの小さなプログラムです。 ノート側に何も書き足さなくていいのは、この「見出しを拾う」部分のおかげです。

~/.claude/skills/_vault/index.shVAULT は STEP 1 のパスに書き換える
#!/usr/bin/env bash
VAULT="$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/Obsidian_VN"
TARGET="${1:-.}"          # 第1引数でフォルダを絞る（省略時は Vault 全体）

# 見つからなくても「失敗」で終わらせない（理由は下の注意書き）
[ -d "$VAULT/$TARGET" ] || { echo "(見つかりません: $VAULT/$TARGET)"; exit 0; }
cd "$VAULT" || exit 0

echo "ルート: $VAULT"
echo

find "$TARGET" -name '*.md' -not -path '*/.obsidian/*' | sort | while IFS= read -r f; do
  # ① summary: があれば最優先で使う
  s=$(grep -m1 '^summary:' "$f" | sed 's/^summary:[[:space:]]*//')
  # ② 無ければ最初の見出し（# で始まる行）を使う
  [ -n "$s" ] || s=$(grep -m1 '^#\{1,3\} ' "$f" | sed 's/^#\{1,3\}[[:space:]]*//')
  # ③ それも無ければファイル名だけで勝負
  [ -n "$s" ] || s='-'
  echo "- ${f#./} : $s"
done
ターミナル置いたら動作確認
mkdir -p ~/.claude/skills/_vault
chmod +x ~/.claude/skills/_vault/index.sh

# VNworks だけの目次が出るか
bash ~/.claude/skills/_vault/index.sh VNworks

# 行数を数える。100 行を大きく超えるなら分割を検討
bash ~/.claude/skills/_vault/index.sh VNworks | wc -l
ここが唯一のワナ：失敗すると全部が止まる

スキルの中で走らせるコマンドは、1 つでも「失敗」で終わるとスキル全体が中止されます。 Claude はメモの中身を一切見られません。

シェルの世界では「終了コード 0 ＝ 成功」「それ以外 ＝ 失敗」。 だから上のスクリプトは、フォルダが無いときも exit 0 で終わります。 set -e は付けないこと（grep が空振りしただけで失敗扱いになります）。

フォルダ名を _vault にした理由

このフォルダには SKILL.md を置きません。スクリプトの置き場所として使うだけです。 SKILL.md が無いフォルダはスキルとして読み込まれないので、 /skills の一覧を汚さずに共有部品を置けます。

STEP 3

案件用のメモを書く

1 枚目のスキルです。~/.claude/skills/vault-works/SKILL.md という名前と場所が決まっていて、 フォルダ名がそのままコマンド名（/vault-works）になります。

~/.claude/skills/vault-works/SKILL.md
---
name: vault-works
description: 過去の案件ノート（Obsidian の VNworks）から実績と経緯を調べる。
  取引先・商材・イベント・納品の話が出たとき、「前回どうした」「あの案件の条件は」
  「◯◯様の件」と聞かれたとき、見積や企画を作る前の下調べに使う。
allowed-tools: Bash(bash ${CLAUDE_SKILL_DIR}/../_vault/index.sh:*) Read
---

## 案件ノート一覧

!`bash ${CLAUDE_SKILL_DIR}/../_vault/index.sh VNworks`

## 手順

1. 上の一覧から、質問に関係しそうなノートを 1〜3 件選ぶ
2. 「ルート:」の行のパスと組み合わせて絶対パスを作り、Read で開く
3. 読んだ内容を根拠に答える。参照したノートのパスを最後に書く
4. 一覧に該当が無ければ「VNworks に該当なし」と言う。推測で埋めない

3 行だけ、意味を説明します

  • description ── 1 回目の選別に使われる唯一の材料。 「何をする」＋「いつ使う」＋「実際に言いそうな言い回し」の 3 点セットで書く。 固有名詞（取引先名や商材名）を入れると、ぐっと当たるようになります。
  • !`...` ── バッククォートで囲んだ行は、Claude が読む前に実行され、その出力に置き換わる。 だから毎回できたての目次が入る。目次ファイルを保存しておく必要はありません。
  • allowed-tools ── 上の行を実行する許可。 これが無いと止まります。差し込みコマンドは「許可しますか？」と聞いてくれず、 許可されていなければ黙って中止されるからです。末尾の :* は「引数は何でもよい」の意味。
${CLAUDE_SKILL_DIR} って何

「この SKILL.md が置いてあるフォルダ」に自動で置き換わる変数です。 本文の中でも allowed-tools の中でも同じように展開されるので、 両方で使えば「同じスクリプトを、許可を聞かれずに実行する」がきれいに成立します。 ../_vault/ と書いているのは、隣のフォルダの共有スクリプトを指すためです。

STEP 4

アーカイブ用のメモを書く

2 枚目。中身はほぼ同じで、フォルダと説明文だけが違います。 こちらは MOC を入口にする手順を足しているのがポイントです。

~/.claude/skills/vault-archive/SKILL.md
---
name: vault-archive
description: 過去の Claude との会話ログとプロジェクト記録（ClaudeArchive）を掘り返す。
  「前に相談した件」「あのとき決めた方針」「同じことを前にやった気がする」と
  言われたとき、過去の検討経緯や結論を確認したいときに使う。
allowed-tools: Bash(bash ${CLAUDE_SKILL_DIR}/../_vault/index.sh:*) Read
---

## アーカイブ一覧

!`bash ${CLAUDE_SKILL_DIR}/../_vault/index.sh ClaudeArchive`

## 手順

1. まず _MOC_ClaudeArchive と _CrossMemory を確認する。
   手で整理された目次なので、機械的な一覧より当たりが早い
2. そこから当たりを付けて、実ファイルを Read で開く
3. 会話ログは長いので、関係する部分だけを引用して答える
4. 見つからなければ「アーカイブに該当なし」と言う
STEP 5

試す

Claude Code はスキルのフォルダを見張っているので、保存した瞬間に反映されます（再起動不要）。 ただし ~/.claude/skills フォルダ自体を今まさに新規作成した場合だけは、一度アプリを開き直してください。

Claude Code の入力欄
// 一覧に 2 枚とも出ているか
/skills

// 手動で呼ぶ（目次がちゃんと出るかの確認）
/vault-works 握手会の商材って過去に何を出した？

// 自動で選ばれるか（本番のテスト）
ブラザー様の案件、前回の条件どうだったっけ

3 つ目で勝手に vault-works が起動すれば完成です。起動しなければ description の言葉が足りていません。 自分が実際に打ちそうな言い回しを、そのまま説明文に足してください。

つまずいたら

症状から引く

こうなったたぶん原因直し方
目次が「見つかりません」だけ VAULT のパス違い ターミナルで ls "$VAULT" が通るか確かめる。スペースを含むので必ず引用符で囲む
Shell command permission check failed allowed-tools の書き方がコマンドと一致していない 本文の ! 行と同じ形になっているか確認。引数を渡すなら末尾に :*
Shell command failed スクリプトが 0 以外で終了した 末尾に || true を足す。set -e を消す
ファイルが読めないと言われる iCloud にまだ実体が降りていない Finder で Vault を「今すぐダウンロード」
自動で起動しない 説明文が抽象的すぎる 取引先名・商材名など固有名詞を説明文に入れる。合計 1,536 文字まで、大事な用途を先頭に
関係ない話でも起動する 説明文が広すぎる 適用条件を狭める。手動専用にするなら disable-model-invocation: true
ノートは選ぶが中身を読まない 手順の書き方があいまい 「Read で開いてから答える」と明示的に書く
iPhone だけで完結させたい この方式はパソコン用 Vault はパソコン側のファイルを読む。iPhone 単体では動かない
知っておくこと

Obsidian の書き方は通じない

Claude が読むのはただの Markdown テキストです。Obsidian が便利に解釈してくれる記法は、 Claude にはただの文字列として届きます。

書き方Obsidian ではClaude では
[[ノート名]]リンクとして開けるただの文字。追いかけられない
![[埋め込み]]中身が展開される展開されない
Dataview クエリ表が生成されるクエリ文がそのまま見える
絶対パスただの文字Read で開ける

だから目次には必ず実際のファイルパスを出しています。 _MOC_ClaudeArchive の中が [[リンク]] だらけなら、Claude はその先までは自動で追えません。 よく使う導線だけでもパスを併記しておくと、目に見えて賢くなります。

安全のはなし

Vault 全体を無条件につながない

SKILL.md として読まれるファイルの中の ! 行は、あなたの権限でそのまま実行されます。 今回の作りでは SKILL.md は自分で書いた 2 枚だけで、Vault のノートはあくまで Read で読まれるデータなので、この危険はありません。

逆に言えば、Vault のノートをそのまま SKILL.md として登録する方式（シンボリックリンクなど）に切り替えるときは、 中身を読んでからにしてください。

クラウド・Cowork では動かない

Vault はこのパソコンの中のファイルです。デスクトップアプリのローカルセッション専用と割り切ってください。 Cowork タブやクラウドセッション、ルーティンからは見えません。

慣れてきたら

伸ばし方

  • 3 枚目を足す ── 運用に慣れたら vault-personal を作って 個人用 / 対人メモ を担当させる。index.sh は引数を変えるだけで使い回せます。
  • PDF も載せる ── index.sh の -name '*.md' を \( -name '*.md' -o -name '*.pdf' \) にすると PDF も目次に載ります。Claude は PDF を直接読めます。
  • 要約を足していく ── 見出しだけでは中身が伝わらないノートに、 Obsidian のプロパティで summary: を 1 行足す。スクリプトはそちらを優先して使います。全部やる必要はありません。
  • 常時コストを削る ── ほとんど使わない時期が来たら、設定の skillOverrides で "name-only" にすると、説明文がカバンから降りて名前だけになります。
