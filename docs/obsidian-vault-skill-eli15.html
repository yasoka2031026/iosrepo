Obsidian_VN × Claude Code × LLM Wiki

Obsidian を司書にする

Vault を 2 つの役割で使う。ひとつは スキルの置き場、もうひとつは Claude の外部記憶。 378 ファイルの Vault を、育つ知識ベースに変えるまでの手順を、前提知識ゼロから順番に。

現状：スキルはまだ 0 個。あるのは別アカウントから移した Claude のアーカイブと、手で書いたメモ。
ここから始めて、最終的にスキル 3 枚とスクリプト 1 本になります。
まず結論

何を作るのか

Claude Code には「スキル」というしくみがあります。 スキル＝ Claude に渡しておく手順書だと思ってください。 「こういうときは、こうやって」と書いた Markdown ファイルを決まった場所に置くと、Claude がそれを読んで動く。

やることは 2 つです。手順書を Vault の中に置いて Claude とつなぐこと。 そして残りのメモを、Claude が必要なときだけ開く外部記憶にすること。 この 2 つは同じ Vault に同居しますが、性質がまったく違うので、置き場所からきっちり分けます。

手順書は「Claude が実行するもの」。
メモは「Claude が参照するもの」。
混ぜない。

下敷きにする考え方

LLM Wiki ── 毎回調べ直さない

Andrej Karpathy 氏が提唱した LLM Wiki は、AI に知識を持たせる方法としてはっきりした型を示しています。 ふつうの RAG（検索してその場で読む方式）は、質問のたびにゼロから資料を漁って、終わったら忘れる。 LLM Wiki はそうしない。資料を一度きり「コンパイル」して Wiki に落とし、以降の質問は Wiki にだけ聞く。

Karpathy 氏の言い方を借りると「Obsidian が IDE、LLM がプログラマ、Wiki がコードベース、あなたは設計者」。 Obsidian を使っている時点で、あなたはこの型に一番近い場所にいます。

構成は 3 層 × 3 操作

source

生の素材

加工していない原材料。あなたの場合は ClaudeArchive/ の会話ログと、手書きのメモ。 ここは触らない。消さない。あとから何度でも汲み直せる井戸として残します。
wiki

整形済みの知識

素材から抽出して、1 ページ 1 トピックに整えたもの。_Wiki/ に作ります。 Claude がふだん読むのはここだけ。今はまだ空っぽで、これから育てます。
schema

維持のルール

「どう取り込み、どう書き、どう直すか」を書いた設計図。 今回はこれを スキルそのものとして _Skills/ に置きます。 ルールが実行可能な形で Vault に入る、というのがこの作りの肝です。

この 3 層に対して、操作も 3 つに決まっています。作るスキルはこれと 1 対 1 で対応させます。

操作やること作るスキル
ingest素材から知識を抜き出して Wiki ページにする/wiki-ingest
queryWiki を引いて答える（日常の 9 割はこれ）/wiki
lint重複・矛盾・リンク切れを見つけて直す/wiki-lint
前提知識

なぜ「メモを全部スキルにする」ではダメなのか

Claude はセッションを開いた瞬間に、すべてのスキルの説明文（description）を暗記した状態で会話を始めます。 本文は読みません。読むのは「使う」と決めたときだけ。

つまり説明文は「常に持ち歩く荷物」です。メモを 378 個スキルにすると、378 行の説明文を毎回カバンに入れて歩くことになる。 重いうえに、似た説明が並んで「どれだっけ」となり、選び間違いも増えます。 だからスキルは 3 枚だけにして、メモは読まれるデータの側に置きます。

図書館でたとえると

Claude は司書、あなたのメモは本、Vault は書庫です。

ダメな方法
本 378 冊を全部カウンターに積んでおく。邪魔だし、探すのに時間がかかる。
やる方法
カウンターには 目次カード 1 枚だけ。司書はそれを見て、書庫から必要な 2〜3 冊だけ取りに行く。

選別は 2 回に分かれている

ここが一番大事なところです。Claude は 2 段階でふるいにかけます。 1 回目は説明文だけを見て、そもそも Wiki を引くべき話かを判断する。 2 回目は目次を見て、どのページを開くかを決める。

1 回目の判断材料は説明文だけなので、説明文の書き方が精度を決めます。 チューニングする場所は 1 か所しかない。効かないと感じたら、まずここを疑ってください。

設計

Vault をどう作り替えるか

いま Obsidian_VN にはスキルがありません。素材だけがある状態です。 そこに _Skills/ と _Wiki/ を新設して、既存フォルダは素材として据え置きます。 アンダースコア始まりにするのは、あなたが既に _MOC_ や _CrossMemory で使っている流儀に合わせるためです。

Obsidian_VN/
├─ _Skills/新設・手順書
│　├─ wiki/SKILL.md
│　├─ wiki-ingest/SKILL.md
│　└─ _lib/index.sh
├─ _Wiki/新設・外部記憶
│　└─ （最初は空。育てていく）
├─ ClaudeArchive/素材（据え置き）
├─ VNworks/素材（据え置き）
├─ 個人用/当面は対象外
└─ 対人メモ/当面は対象外
スキルを Vault に置くと何がうれしいか

Obsidian の画面で手順書を書き足せること。そして iCloud で同期されるので、 スキルの定義そのものがバックアップされ、他のパソコンでも使い回せること。 Claude Code 側にはショートカット（シンボリックリンク）を置くだけで、実体は Vault に一本化されます。

個人用 / 対人メモ を最初に外す理由

技術的な問題ではなく、切り分けの問題です。仕事の質問をしたときに人物メモが引っ張られてくると、 邪魔なうえに意図しない情報が会話に混ざります。まず仕事側で運用感をつかんでから足すのが安全です。

実装

手を動かす

STEP 1

パソコン側の Vault の場所を突き止める

iPhone の Obsidian は iCloud 経由で同期していることがほとんどです。 その場合 Mac 側の実体は、長いパスの奥にあります。まず居場所を確認します。

ターミナルMac
# iCloud 同期の Obsidian はここ
ls ~/Library/Mobile\ Documents/iCloud~md~obsidian/Documents/

# 見つからなければ名前で探す（少し時間がかかる）
find ~ -maxdepth 6 -type d -name "Obsidian_VN" 2>/dev/null

出てきたパスを控えます。以降 $VAULT と書いてある部分に入ります。

ターミナルこの先ずっと使うので変数にしておく
export VAULT="$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/Obsidian_VN"
ls "$VAULT"   # 中身が出れば正解
iCloud の「まだ降りてきてない」問題

iCloud はディスク節約のため、中身を実際にはダウンロードせず「見出しだけ」の状態でファイルを置くことがあります。 この状態のファイルは読もうとすると失敗します。

Finder で Vault フォルダを右クリック →「今すぐダウンロード」で全部降ろしておくのが確実です。

STEP 2

3 層のフォルダを掘る

ターミナル
mkdir -p "$VAULT/_Skills/_lib"
mkdir -p "$VAULT/_Skills/wiki"
mkdir -p "$VAULT/_Skills/wiki-ingest"
mkdir -p "$VAULT/_Wiki"

Obsidian を開くと、これらが普通のフォルダとして見えるようになります。 以降の編集は Obsidian からでも、エディタからでも、どちらでも構いません。

STEP 3

目次を作るスクリプトを置く

指定したフォルダの .md を全部さらって、「パス ＋ その中の最初の見出し」の一覧を出すだけの小さなプログラムです。 ノート側に何も書き足さなくていいのは、この「見出しを拾う」部分のおかげです。

$VAULT/_Skills/_lib/index.shVAULT= の行だけ書き換える
#!/usr/bin/env bash
VAULT="$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/Obsidian_VN"
TARGET="${1:-.}"          # 第1引数でフォルダを絞る（省略時は Vault 全体）

# 見つからなくても「失敗」で終わらせない（理由は下の注意書き）
[ -d "$VAULT/$TARGET" ] || { echo "(見つかりません: $VAULT/$TARGET)"; exit 0; }
cd "$VAULT" || exit 0

echo "ルート: $VAULT"
echo

find "$TARGET" -name '*.md' -not -path '*/.obsidian/*' | sort | while IFS= read -r f; do
  # ① summary: があれば最優先で使う
  s=$(grep -m1 '^summary:' "$f" | sed 's/^summary:[[:space:]]*//')
  # ② 無ければ最初の見出し（# で始まる行）を使う
  [ -n "$s" ] || s=$(grep -m1 '^#\{1,3\} ' "$f" | sed 's/^#\{1,3\}[[:space:]]*//')
  # ③ それも無ければファイル名だけで勝負
  [ -n "$s" ] || s='-'
  echo "- ${f#./} : $s"
done
ターミナル動作確認
chmod +x "$VAULT/_Skills/_lib/index.sh"

# VNworks の目次が出るか
bash "$VAULT/_Skills/_lib/index.sh" VNworks

# 行数を数える。100 行を大きく超えるならフォルダを分ける合図
bash "$VAULT/_Skills/_lib/index.sh" VNworks | wc -l
ここが唯一のワナ：失敗すると全部が止まる

スキルの中で走らせるコマンドは、1 つでも「失敗」で終わるとスキル全体が中止されます。 Claude は手順書の中身を一切見られません。

シェルの世界では「終了コード 0 ＝ 成功」「それ以外 ＝ 失敗」。 だから上のスクリプトは、フォルダが無いときも exit 0 で終わります。 set -e は付けないこと（grep が空振りしただけで失敗扱いになります）。

STEP 4

query スキルを書く ── 日常の主役

Wiki を引いて答える係です。$VAULT/_Skills/wiki/SKILL.md を作ります。 フォルダ名（wiki）がそのままコマンド名（/wiki）になります。

$VAULT/_Skills/wiki/SKILL.md
---
name: wiki
description: 個人の外部記憶（Obsidian の _Wiki と過去の案件ノート）を引いて答える。
  過去の決定、取引先や案件の経緯、自分のやり方や手順を聞かれたとき、
  「前どうしたっけ」「あの件の条件は」「うちのやり方は」と聞かれたときに使う。
allowed-tools: Bash(bash ${CLAUDE_SKILL_DIR}/../_lib/index.sh:*) Read Grep Glob
---

## Wiki 目次

!`bash ${CLAUDE_SKILL_DIR}/../_lib/index.sh _Wiki`

## 案件ノート目次（Wiki 未整備分の素材）

!`bash ${CLAUDE_SKILL_DIR}/../_lib/index.sh VNworks`

## 手順

1. まず _Wiki の目次から探す。整形済みなので当たりが早い
2. 見つからなければ案件ノートの目次を見る
3. 「ルート:」の行のパスと組み合わせて絶対パスを作り、Read で開く
4. 本文に [[ページ名]] があり、その先が必要なときは
   Glob で `**/ページ名.md` を探して開く
5. 答えるときは、根拠にしたファイルのパスを必ず最後に並べる
6. どこにも無ければ「Wiki に該当なし」と言う。推測で埋めない
7. 調べた結果が今後も使えそうなら、最後に
   「これは _Wiki に残しますか？」と一言添える

3 行だけ、意味を説明します

  • description ── 1 回目の選別に使われる唯一の材料。 「何をする」＋「いつ使う」＋「実際に言いそうな言い回し」の 3 点セット。 取引先名や商材名などの固有名詞を入れると、ぐっと当たるようになります。
  • !`...` ── バッククォートで囲んだ行は、Claude が読む前に実行され、その出力に置き換わる。 だから毎回できたての目次が入ります。目次ファイルを保存しておく必要はありません。
  • allowed-tools ── 上の行を実行する許可。 これが無いと止まります。差し込みコマンドは「許可しますか？」と聞いてくれず、 許可されていなければ黙って中止されるからです。末尾の :* は「引数は何でもよい」の意味。
手順 4 が [[リンク]] 問題の答え

Obsidian の [[ページ名]] は、Claude にとってはただの文字列で、自動では追えません。 でも「見つけたら Glob で探して開け」と手順に書いておけば、実質的にリンクをたどれるようになります。 禁止するのではなく、たどり方を教えるのが正解です。

STEP 5

Claude Code とつなぐ ── ここが連動の正体

Claude Code がスキルを探すのは ~/.claude/skills/ だけです。 でも実体を Vault に置いたまま使いたい。そこでショートカット（シンボリックリンク）を置きます。 公式に「スキルの登録はシンボリックリンクでよく、リンク先の SKILL.md を読む」と決められている、正規のやり方です。

ターミナルスキル 1 枚につき 1 回だけ
mkdir -p ~/.claude/skills

ln -s "$VAULT/_Skills/wiki"        ~/.claude/skills/wiki
ln -s "$VAULT/_Skills/wiki-ingest" ~/.claude/skills/wiki-ingest

# 確認：リンク先が Vault を指していれば成功
ls -l ~/.claude/skills/

以降、Obsidian で _Skills/wiki/SKILL.md を編集すれば、それがそのまま Claude の挙動になります。 スキルを Obsidian で育てられる状態ができました。

_lib と _Wiki にはリンクを張らない

リンクを張るのは SKILL.md を持つフォルダだけです。 _lib はスクリプト置き場、_Wiki は読まれるデータなので、 Claude Code に登録する必要はありません。登録すると /skills の一覧が散らかります。

STEP 6

ingest スキルを書く ── Wiki を育てる

_Wiki は今まっさらです。これを埋めるのが ingest。 アーカイブや案件ノートから知識を抜き出して、1 ページ 1 トピックに整えて書き出します。 手動で呼ぶ専用にします（勝手にファイルを作られると困るため）。

$VAULT/_Skills/wiki-ingest/SKILL.md
---
name: wiki-ingest
description: 過去ログや案件ノートから知識を抜き出して _Wiki のページにする。
disable-model-invocation: true
argument-hint: [調べたいテーマ or 素材のパス]
allowed-tools: Bash(bash ${CLAUDE_SKILL_DIR}/../_lib/index.sh:*) Read Grep Glob Write
---

テーマ: $ARGUMENTS

## 素材の目次

!`bash ${CLAUDE_SKILL_DIR}/../_lib/index.sh ClaudeArchive`

## 手順

1. テーマに関係する素材を目次から選び、Read で読む
2. 事実・決定・数字・固有名詞だけを残し、会話の流れは捨てる
3. 下の書式で 1 ページにまとめ、_Wiki/ に新規ファイルとして書く
4. 既に同じテーマのページがあれば、新規作成せず追記・更新する
5. 最後に、作ったページのパスと要約を報告する

## ページの書式

---
summary: （このページを一言で。「いつ開くべきか」を含める）
updated: YYYY-MM-DD
source: （元にした素材のパス。複数可）
---

# タイトル

## 要点
- 箇条書き 3〜7 行。ここだけ読めば用が足りる状態にする

## 詳細
（必要な分だけ）

## 関連
- [[別のページ名]] — なぜ関連するかを一言
なぜ「会話の流れは捨てる」のか

過去ログをそのまま置いても Wiki にはなりません。長いだけで、読むたびにコンテキストを食います。 LLM Wiki の肝は一度きちんと蒸留して、以降はそれだけを読むこと。 手間を最初に 1 回払って、あとは何度でも安く引く、という取引です。

STEP 7

試す

Claude Code はスキルのフォルダを見張っているので、保存すればたいてい即反映されます。 反映されないと感じたら、一度アプリを開き直してください。 ~/.claude/skills を今まさに新規作成した場合は、必ず開き直しが要ります。

Claude Code の入力欄
// 一覧に wiki と wiki-ingest が出ているか
/skills

// まず素材から Wiki を 1 ページ作ってみる
/wiki-ingest 握手会の商材まわりで過去に決めたこと

// できたページが引けるか（自動起動のテスト）
握手会の商材って、前回どういう条件だった？

最後の質問で勝手に wiki が起動すれば完成です。起動しなければ description の言葉が足りていません。 自分が実際に打ちそうな言い回しを、そのまま説明文に足してください。

知っておくこと

境界と安全

Obsidian の書き方は自動では通じない

書き方Obsidian ではClaude では
[[ページ名]]リンクとして開けるただの文字。手順に書けば Glob で追える
![[埋め込み]]中身が展開される展開されない
Dataview クエリ表が生成されるクエリ文がそのまま見える
絶対パスただの文字Read で開ける

だから目次には実際のファイルパスを出し、[[ ]] は「見つけたら探しに行け」と手順で補っています。 人間向けの表記と機械向けの表記を、両方まかなう形です。

スキルとデータの線引き

Vault の一般ノートを SKILL.md にしない

SKILL.md として読まれるファイルの中の ! 行は、あなたの権限でそのまま実行されます。 今回の作りでは SKILL.md は _Skills/ の下の自作 2 枚だけで、 他のノートはすべて Read で読まれるデータです。この境界を守るかぎり危険はありません。

別アカウントから移した ClaudeArchive の中身も同じ扱いです。 素材として読むだけなら安全。スキルとして登録するのはやめてください。

クラウド・Cowork では動かない

Vault はこのパソコンの中のファイルです。デスクトップアプリのローカルセッション専用と割り切ってください。 Cowork タブやクラウドセッション、ルーティンからは見えません。

段取り

どの順でやるか

全部を一度に作らないでください。Wiki は「作る」ものではなく「育つ」ものです。

時期やることねらい
今日 STEP 1〜5。wiki スキル 1 枚だけを動かす 目次が出て、ノートが読まれることを目で確認する
今週 wiki-ingest で、よく聞かれるテーマを 5〜10 ページ作る Wiki が「引くと役に立つ」状態の最低ラインに乗る
ひと月 調べもののたびに 1 ページ足す。updated を更新する 使うほど強くなる状態に入る
そのあと wiki-lint を足す。個人用・対人メモ を対象に加える 重複と矛盾を潰し、守備範囲を広げる
lint スキルは後回しでいい

ページが 30 枚を超えたあたりから、重複や古い記述が出てきます。そこで初めて作れば十分です。 中身は「_Wiki の全ページの summary と updated を一覧にして、重複・矛盾・3 か月以上古いページを指摘する」だけ。 index.sh をそのまま使い回せます。
