結論

Mac に入れて、iOS 開発の「並列試作」と「シミュレータ検証」に使う。承認は iPhone から。

Orca は AI モデルではありません。すでに契約しているエージェントの CLI を起動し、git worktree（同じリポジトリから枝分かれした別フォルダ）ごとに 1 つずつ割り当てて並べる「エージェント開発環境（ADE）」です。料金は Orca 側にはかからず、各エージェントのサブスクリプションをそのまま使います。

orca emulator で iOS Simulator をタップ・入力・画面構造の取得まで自動化。クラウド環境ではできない検証です。

01

Orca とは何か

公式の説明をかみ砕くと

Orca は、米国の Stably AI（Y Combinator 出資のスタートアップ）が開発している Electron 製のデスクトップ IDE です。公式ドキュメントは「複数の AI コーディングエージェントを並べて動かすためのデスクトップ IDE」と説明しています。タスクを 1 つ作るたびに、専用の git worktree、専用のエージェント用ターミナル、専用のブラウザタブが用意されます。

ブランチを切り替えたり git stash で作業を退避したりする必要がありません。エージェント同士が同じファイルを同時に書き換える事故も、フォルダが分かれているので起きません。

向いている人

  • 同じバグを 3 つのエージェントに並行して解かせ、勝者を選びたい
  • AI が書いた差分を、きちんとレビューしてから出荷したい
  • Claude Code・Codex・Cursor CLI などをすでに契約していて、操作を 1 か所にまとめたい
  • SSH 先や常時稼働のサーバーでエージェントを動かしたい

Orca ではないもの

  • モデルではない。Claude や Codex の契約は各自で用意する
  • git の代わりではない。作られるのは本物の git worktree で、普通の git コマンドがそのまま使える
  • ホスティングサービスではない。既定ではローカルで動き、リモートも自分の管理するマシンを使う
  • ノーコードツールではない。差分を読み、コミットを管理できる開発者が前提

03

中核の仕組み：worktree

並列で動かしても壊れない理由

git worktree は、1 つのリポジトリから複数の作業フォルダを同時に取り出せる git の標準機能です。履歴（.git）は共有したまま、ブランチごとに別のフォルダができます。Orca はこれを「タスク 1 件につき 1 つ」自動で作り、片付けまで面倒を見ます。

新しい worktree に「足りないもの」を補う 3 つの方法

新しく作った worktree は、git で管理されているファイルしか入っていない「まっさらな状態」です。.gitignore に入っている秘密情報やキャッシュは自動ではコピーされません。Orca はこれを 3 通りの方法で補います。

方法置き場所動作向いているもの
Worktree Shared Paths設定 → Repository（個人設定）macOS では APFS のクローンコピー、できなければシンボリックリンク自分だけが使う共有パス
worktree.sharedDirectoriesリポジトリ直下の orca.yamlメインのフォルダを共有（リンク）大きくて再生成できるもの。node_modules など
.worktreeincludeリポジトリ直下worktree ごとに実体をコピー.env、秘密情報入りの設定ファイル

いずれも「gitignore されていて、メインのフォルダに実在するパス」だけが対象です。.worktreeinclude はワイルドカードに未対応で、パスを 1 行ずつそのまま書きます。

さらに orca.yaml の scripts.setup / scripts.archive に、worktree の作成時・アーカイブ時に走らせるコマンドを書けます（設定画面の Repository → Hooks からも登録可能）。

05

主要機能

見る・書く・確かめる・任せる、の 4 系統

見る（監視と切り替え）

エージェントの状態表示

作業中は回転アイコン、入力待ちは琥珀色の「？」、完了は緑、失敗は赤。タブを開かなくても状況がわかります。Claude Code や Codex が出すターミナルのタイトル信号とフックから判定します。

Agent Dashboard

全 worktree のエージェントを「要対応・作業中・完了・待機」の 4 列で並べるかんばん。実験的機能で、設定の Experimental から有効化します。別ウィンドウにも出せます。

通知と未読

作業中から待機に変わった瞬間に OS 通知・音・チップで知らせます。macOS では Dock アイコンに未読数を表示。通知ごとに未読へ戻せます。

Cmd-J ジャンプ

worktree・タブ・最近のセッションを横断検索。Cmd-1〜6 で直近 6 件のセッションへ直接移動できます。Cmd-P は worktree 内のファイル検索です。

使用量とアカウント切り替え

Claude・Codex などの使用量とリセットまでの時間をステータスバーに表示し、80% を超えると警告。複数アカウントを再ログインなしで切り替えられます。

モバイルコンパニオン

iOS（App Store）と Android（APK）で提供、現在はベータ版。状態の確認、返答、音声入力、ステージングとコミットまでできます。

書く（編集とレビュー）

高速ターミナル

WebGL 描画、画面分割は無制限、スクロール履歴はアプリを再起動しても残ります。初回起動時に Ghostty の設定を取り込めます。

Annotate AI Diff

差分の行にコメントを付け、最後にまとめて 1 回でエージェントへ送ります。1 件ずつ送るとエージェントの修正が行ったり来たりするため、という設計意図です。

Attribution

どの行を AI が書き、どの行を人が書いたかを差分の余白に表示。記録は Orca 内だけに残り、git にはコミットされません。

VS Code 系エディタ

Monaco エディタを内蔵し、自動保存に対応。ファイルや画像をエージェントの入力欄へドラッグで渡せます。Markdown・画像・PDF のプレビュー付き。

GitHub / Linear / Jira

PR・Issue・ボードをアプリ内で閲覧し、そこから直接 worktree を作成。ブランチ名は Issue や PR から自動で決まります。

Chat UI

ターミナルの上にチャット形式の表示を重ねる実験的機能。Claude・Codex・Grok・OMP に対応し、モデル切り替えや質問カードへの回答ができます。

確かめる（動作検証）

内蔵ブラウザと Design Mode

本物の Chromium 上で UI 要素をクリックすると、その HTML・計算済み CSS・切り抜き画像がエージェントの入力に入ります。

iOS / Android エミュレータ操作

orca emulator で iOS Simulator を操作。タップ、ジェスチャー、文字入力、回転、アクセシビリティツリーの取得ができます。

Computer Use

エージェントがデスクトップアプリを、アクセシビリティ情報を手がかりに操作します。実際の画面操作が必要な作業向けです。

任せる（自動化）

Orca CLI

worktree 作成、ターミナルへの送信、ブラウザ操作を orca コマンドで実行。エージェント自身が Orca を操作できます。

定期実行（Automations）

「平日 9 時に Issue を整理」のような定期プロンプトを登録。事前チェックのコマンドが失敗した回はスキップできます。

オーケストレーション

まとめ役のエージェントがタスクを分割し、別のエージェントに割り振って完了報告を受け取る仕組み。実験的機能です（09 で詳述）。

ハイバネーション

完了から一定時間（既定 30 分）触っていないエージェントを停止してメモリを空け、開き直すと claude --resume などで自動再開します。実験的機能。

Skills

npx skills add で Orca 用スキルをエージェントに入れると、エージェントが Orca の CLI を正しく使えるようになります。

Continue in New Session

会話が長くなったら、要約付きの引き継ぎプロンプトで新しいセッションを開始。別のエージェントへの引き継ぎも可能です。

06

導入手順

Mac（Apple Silicon）を想定。所要時間は 15 分前後

  1. Orca 本体を入れる

    Homebrew が入っていれば 1 行で済みます。安定版チャネルを自動で追いかけます。

    brew install --cask stablyai/orca/orca
# 以後の更新
brew upgrade --cask orca

    直接ダウンロードする場合は GitHub Releases の orca-macos-arm64.dmg（Intel Mac は orca-macos-x64.dmg）。署名・公証済みです。

  2. 使うエージェントの CLI を入れて、一度ログインする

    Orca はエージェント本体を同梱していません。普通のターミナルで一度ログインしておけば、Orca が ~/.claude と ~/.codex を自動で読み取ります。

    # Claude Code（公式の推奨手順が変わっている場合は Anthropic のドキュメントに従う）
npm i -g @anthropic-ai/claude-code
claude          # 初回にブラウザでログイン

# Codex
npm i -g @openai/codex
codex           # 初回にログイン

  3. 初回起動

    ホームフォルダへのアクセス許可を求められます。続いて ~/.claude・~/.codex・Ghostty の設定を取り込むか聞かれるので、取り込んでおくと楽です。

  4. 権限モードを Manual に切り替える

    ここは最初に必ず確認してください。Orca は既定で、各エージェントの「確認なしで実行」フラグを付けて起動します（詳しくは 07）。設定 → Agents → Agent Permissions で Manual を選ぶと、通常の確認つき起動に戻ります。

  5. Orca CLI を登録し、スキルを入れる

    設定 → General → Orca CLI で orca コマンドを PATH に登録します。続けて、エージェントに Orca の操作方法を教えるスキルを入れます。

    orca status --json
npx skills add https://github.com/stablyai/orca --skill orca-cli --global
npx skills add https://github.com/stablyai/orca --skill orca-emulator --global   # iOS 開発なら
npx skills add https://github.com/stablyai/orca --skill orchestration --global   # 任意

  6. リポジトリ側の設定を置く（iOS 向けの例）

    worktree を作るたびに必要な準備を自動化します。以下は iosrepo に置く場合の例です。秘密情報のファイル名は実際のプロジェクトに合わせてください。

    # orca.yaml（リポジトリ直下）
scripts:
  setup: |
    xcodebuild -resolvePackageDependencies -derivedDataPath .build/DerivedData

# .worktreeinclude（リポジトリ直下・gitignore 済みのファイルだけが対象）
Config/Secrets.xcconfig

    .build/ はこのリポジトリの .gitignore に既に入っているため、worktree ごとのビルド成果物置き場としてそのまま使えます。

  7. iPhone とペアリングする（任意）

    App Store で「Orca IDE」を入れ、デスクトップのアカウントメニューからペアリングコードを表示して入力します。Orca Relay 経由のペアリングにはサインインが必要です。LAN か Tailscale で直接つなぐこともできます。

  8. 匿名利用統計の送信を止める（任意）

    Orca はプロンプトやコード、リポジトリ名を送らないと明記していますが、匿名の利用状況は既定で送信します。設定 → Privacy でオフにするか、環境変数 ORCA_TELEMETRY_DISABLED=1 を設定します。

07

権限とセキュリティ

便利さと引き換えにしているもの

既定では「確認なし」で起動する

Orca は新しく起動するエージェントに、次のフラグを自動で付けます。worktree そのものを砂場とみなし、ツール実行のたびに止まらないようにする設計です。

Claude Code--dangerously-skip-permissions
Codex--dangerously-bypass-approvals-and-sandbox
Gemini・Cursor ほか--yolo

ところが公式ドキュメント自身が「worktree は隔離されたチェックアウトであって、セキュリティ上のサンドボックスではない」と注意しています。エージェントは、プロセスが触れる範囲のファイルやネットワークにアクセスできます。信頼できる作業以外は Manual を選ぶのが公式の推奨です。

  • 個別のエージェントだけ挙動を変えたいときは、設定 → Agents で該当エージェントの起動引数を書き換えます。書き換えたエージェントは、全体の Yolo / Manual 切り替えの影響を受けなくなります。
  • SSH 接続では known_hosts を照合し、ホスト鍵が変わった場合はパスワードを聞く前に接続を拒否します。
  • スキルの共有リンクは、リンクを知っていれば誰でもインストールできます。パスワードと同じ扱いが必要です。
  • 匿名統計の送信先は PostHog Cloud（米国リージョン）。オフにする方法は 06 の手順 8 を参照してください。

完全な隔離が欲しいときに

Remote Orca Server の手軽な作り方は、両方のマシンに Orca と Tailscale を入れ、サーバー側の設定 → Remote Orca Servers で接続リンクを発行し、クライアント側で貼り付ける方法です。画面のない Linux サーバーなら orca-ide serve --pairing-address <Tailscale のアドレス> で起動します。

Linux では、画面読み上げソフト GNOME Orca と名前が重なるため、CLI 名が orca-ide になります。Orca 内のターミナルでは orca のままで動きます。

09

オーケストレーション

エージェントがエージェントを指揮する

単発の指示なら orca terminal send で足ります。誰が何を担当し、終わったかどうかを追跡したい場合に使うのがオーケストレーションです。設定 → Experimental で有効化します。

orca orchestration run-create --objective "設定画面の改修を分担して進める" --json
orca orchestration task-create --spec "SettingsView のレイアウト崩れを修正" --task-title "Layout" --json
orca orchestration worker-start --task <taskId> --worktree new-child --name layout-fix --agent codex --setup run --json
orca orchestration check --wait --types worker_done,escalation,question --timeout-ms 900000 --json

コマンドのフラグはアプリの版ごとに変わります。エージェントには、使う前に orca skills get orchestration --full で最新の手順を読ませるのが公式の推奨です。旧コマンド orca orchestration run は廃止済みで、実行しても何も起きません。

  • .gitignore は Xcode・Swift Package Manager・CocoaPods・Carthage・fastlane 向けのテンプレート

  • iPhone の Claude アプリからもセッションを確認している

ユースケース 1

SwiftUI 画面を 3 社のエージェントで競作する

向く場面：仕様が固まっていて、実装の選択肢が複数ありそうな画面

  1. Cmd-J で settings-screen と入力し、Create worktree で作成。同じ分岐元から -2、-3 も作る
  2. それぞれに Claude Code・Codex・Cursor CLI を割り当て、同じ指示を貼る
  3. 3 つのタブを画面の端にドラッグして分割し、進み具合を並べて見る
  4. 終わったら各 worktree の差分を開き、気になる行にコメント。いちばん筋のよい案へまとめて返す
  5. 採用案からコミット・プッシュ・PR 作成。残り 2 つは削除する
指示の例：
SettingsView を SwiftUI で実装してください。
- 通知 ON/OFF、言語選択、ログアウトの 3 項目
- iOS 17 以降、NavigationStack を使用
- 既存の AppTheme の色定義を使うこと
- 実装後、xcodebuild でビルドが通ることを確認すること

3 案のうち 2 案が同じ構成を選んだなら、その構成はおそらく妥当です。全員が違う構成になった箇所は、仕様があいまいな可能性を疑います。

ユースケース 2

エージェントにシミュレータで動作確認までさせる

向く場面：画面遷移やタップ操作を伴う修正の検証

# エージェントに実行させる一連のコマンド（スキーム名・Bundle ID は実際の値に置き換え）
xcodebuild -scheme MyApp -destination 'platform=iOS Simulator,name=iPhone 16 Pro' \
  -derivedDataPath .build/DerivedData build
xcrun simctl install booted .build/DerivedData/Build/Products/Debug-iphonesimulator/MyApp.app
xcrun simctl launch booted com.example.MyApp

orca emulator attach "iPhone 16 Pro" --json
orca emulator ax --json                 # 画面の要素と位置を取得
orca emulator tap 0.5 0.82 --json       # 座標は 0〜1 の比率で指定
orca emulator type "test@example.com" --json
xcrun simctl io booted screenshot evidence.png
orca emulator kill --json               # 終わったら必ず解放

タップ位置は ax で得た要素の中心（x + 幅 ÷ 2、y + 高さ ÷ 2）を使うと安定します。type は半角英数字（US-ASCII）のみ対応のため、日本語入力の検証はできません。

ユースケース 3

設計書を「書く役」と「批判する役」に分ける

向く場面：docs/ にあるようなブループリントや仕様書の作成

  1. worktree spec-draft で Claude Code に設計書の初稿を書かせる
  2. 同じ worktree に 2 つ目のターミナルを開いて Codex を起動し、「矛盾・抜け・実装不能な箇所を指摘して」と依頼する
  3. 指摘のうち採用するものだけを差分の該当行にコメントし、Claude Code へまとめて返す
  4. Markdown プレビューで仕上がりを確認し、PR にする

別の会社のモデルにレビューさせると、同じモデルでの自己レビューでは見落としがちな前提の誤りに気づきやすくなります。

ユースケース 4

外出中は iPhone で「入力待ち」だけ処理する

向く場面：長めのタスクを複数走らせて席を外すとき

  1. 出かける前に 2〜3 本の worktree でエージェントを起動しておく
  2. エージェントが確認を求めると iPhone に通知が届く
  3. Orca モバイルで内容を読み、「yes」や追加の指示を返す。音声入力も使える
  4. 小さな修正なら、モバイルの Source Control でステージングとコミットまで済ませる

ローカル実行の場合、Mac がスリープすると止まります。外出が長いなら、Mac mini などを Remote Orca Server にするか、作業を Claude Code on the web へ回します。

ユースケース 5

平日の朝に Issue の整理を自動で済ませる

向く場面：Issue や PR が増えてきたとき

orca automations create \
  --name "平日の Issue 整理" \
  --trigger weekdays --time 08:45 --timezone Asia/Tokyo \
  --prompt "新しい Issue を読み、優先度と再現手順の有無を整理して一覧にまとめて" \
  --provider claude \
  --repo iosrepo \
  --disabled --json

orca automations run <automationId> --json       # まず手動で試す
orca automations edit <automationId> --enabled --json

最初は --disabled で作成し、手動実行で中身を確かめてから有効にするのが公式の手順です。--precheck に軽いコマンドを指定すると、新しい Issue がない日は実行をスキップできます。

ユースケース 6

使用量の上限に合わせてエージェントを振り分ける

向く場面：Claude の週間上限が近づいたとき

  1. ステータスバーの使用量表示で、各サービスの残量とリセット時刻を確認する
  2. 上限が近いサービスの作業は、余裕のあるエージェントへ「Continue in New Session」で引き継ぐ
  3. 引き継ぎ先は要約された文脈から再開するので、最初から説明し直す必要はない

表示は各 CLI がディスクに書いた記録を読んでいるため、リアルタイムではありません。厳密な請求額は各サービスの管理画面で確認します。

注意点と制約

導入前に知っておくと困らないこと

iOS 開発ならではの注意

  • project.pbxproj の衝突。並列のブランチがそれぞれファイルを追加すると、マージ時に Xcode のプロジェクトファイルが衝突しやすくなります。Xcode 16 以降の「フォルダ同期（buildable folder）」を使うと、ファイル追加で pbxproj が書き換わらなくなり、衝突が減ります。
  • ビルドの重さとディスク容量。Xcode の DerivedData は作業フォルダのパスごとに分かれるため、worktree を増やすたびにフルビルドが走り、容量も増えます。並列数は 3 本程度から始めるのが無難です。
  • シミュレータ操作は手元の Mac だけ。SSH 先やリモートの worktree からは使えません。
  • Xcode の更新に弱い。iOS 側の操作は Simulator の非公開 API を使っているため、Xcode の更新で挙動が変わる可能性があると公式が明記しています。

Orca 全般の注意

  • 既定は確認なし起動。07 のとおり、Manual への切り替えを推奨します。
  • 実験的機能が多い。Agent Dashboard、オーケストレーション、Chat UI、ハイバネーション、Cloud VM は設定の Experimental 配下です。仕様の変更が頻繁にあります。
  • 更新がとても速い。公式は「毎日リリースしており、機能一覧は常に古い。リリースノートが本当の機能一覧」としています。本資料の内容も 2026 年 10 月 1 日時点です。
  • モバイルはベータ版。デスクトップとモバイルの版が離れすぎると接続できなくなるため、両方を最新に保ちます。
  • エージェントの状態表示が出ない場合。CLI を手で打って起動したセッションは認識されないことがあります。ターミナル上部の一覧から起動します。
