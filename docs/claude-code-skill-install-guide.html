スキルを 1 つだけ入れる

00 — 前提

3 つのルートのどれか

スキルの実体は SKILL.md という 1 枚の Markdown ファイル。 どこに置く（＝どう配る）かでルートが変わる。個別スキルを 1 つ自分用に入れるなら A でよい。

ルート A — 手動配置

ファイルを置いて反映させる

1

置き場所を決める

「自分がどこでも使う」なら個人スキル、「このリポジトリの作業だけ」ならプロジェクトスキル。迷ったら個人。

種別パス効く範囲Git 共有
個人 ~/.claude/skills/<name>/SKILL.md 自分の全プロジェクト されない
プロジェクト .claude/skills/<name>/SKILL.md そのリポジトリのみ コミットすれば共有
プラグイン <plugin>/skills/<name>/SKILL.md プラグイン有効時 マーケットプレイス経由

同名が衝突したときの優先順位は エンタープライズ → 個人 → プロジェクト。 プラグインのスキルだけは /plugin-name:skill-name という名前空間になるので衝突しない。

フォルダ名がそのままコマンド名

~/.claude/skills/release-notes/ なら /release-notes で呼べる。 英小文字とハイフンで付けるのが無難。

2

フォルダを作る

デスクトップアプリなら内蔵ターミナルのペインを開いて実行するのが早い。Finder／エクスプローラーで作ってもよい。

TerminalmacOS / Linux
# 個人スキル（どのプロジェクトでも使える）
mkdir -p ~/.claude/skills/release-notes

# プロジェクトスキル（リポジトリのルートで）
mkdir -p .claude/skills/release-notes
PowerShellWindows
mkdir "$env:USERPROFILE\.claude\skills\release-notes"

Windows の ~ は C:\Users\<ユーザー名>。 Finder では ⌘ + ⇧ + G に ~/.claude/skills を入力すると隠しフォルダに飛べる。

3

SKILL.md を置く

中身は YAML の frontmatter（--- で挟む）と、その下の 本文だけ。 frontmatter は全項目が任意だが、description は必ず書く。Claude が「いつこのスキルを使うか」を判断する唯一の手がかりになる。

~/.claude/skills/release-notes/SKILL.md
---
name: release-notes
description: 直近のコミットからリリースノートを日本語で作る。
  リリースノート、変更履歴、CHANGELOG を求められたときに使う。
disable-model-invocation: true
allowed-tools: Bash(git log:*) Read
---

## 直近のコミット

!`git log --oneline -n 30`

## 手順

上のコミットを「機能追加 / 修正 / 内部変更」に分類し、
ユーザー視点の言葉で各 1 行にまとめる。破壊的変更は先頭に置く。
  • !`コマンド` の行は、Claude が読む前に実行され、出力に置き換わる（動的コンテキスト注入）。
  • disable-model-invocation: true を付けると自動発動しなくなり、/release-notes と打った時だけ動く。
  • 本文は毎ターンのコンテキストに残り続けるので、経緯や理由ではなく「何をするか」を短く書く。
4

反映を確認する

Claude Code はスキルのフォルダを監視していて、追加・編集・削除はセッションを開いたまま反映される。 プロンプト欄で /skills を実行し、一覧に出ていれば導入完了。

  • プロンプト欄に / を打つ、または ＋ボタン → スラッシュコマンド でも一覧を確認できる。
  • /context ではどのスキルがコンテキストに載っているかが見える。
ここだけ再起動が要る

skills フォルダ自体をこのセッション開始後に新規作成した場合、監視対象になっていない。 一度アプリ（セッション）を開き直す。

5

呼び出す

使い方は 2 通り。どちらでも同じスキルが走る。

プロンプト欄
// 明示的に呼ぶ — フォルダ名がそのままコマンド
/release-notes

// description に合致すれば Claude が自動で読み込む
今回のリリースの変更履歴をまとめて
引数も渡せる

/release-notes v2.1.0 のように後ろに書いた文字列は、本文中の $ARGUMENTS に展開される。位置指定は 0 始まりで、1 つ目が $0、2 つ目が $1。 frontmatter の arguments で名前を付ければ $version のようにも書ける。

リファレンス

frontmatter 早見表

よく使うものだけ。全フィールドは公式ドキュメントの frontmatter reference を参照。

フィールド効果例
description何をするか／いつ使うか。自動発動の判断材料。実質必須PR を要約する。レビュー依頼時に使う
name一覧での表示名。省略時はフォルダ名release-notes
disable-model-invocationtrue で自動発動を止め、手動呼び出し専用にするtrue
user-invocablefalse で / メニューから隠し、Claude 専用の知識にするfalse
allowed-toolsそのターンだけ許可を聞かずに使えるツールRead Grep
argument-hint補完時に出る引数のヒント[version]
paths該当ファイルを扱っているときだけ自動発動させるsrc/**/*.swift
contextfork でサブエージェントとして別コンテキストで実行fork
model / effortそのスキル実行中だけモデル・推論量を切り替えるeffort: high
ルート C に回すなら 6 つだけ

claude.ai にアップロードして同期させるスキルで使えるのは name / description / license / compatibility / metadata / allowed-tools の 6 つ。 それ以外（argument-hint など）が入っているとアップロード時にエラーで弾かれる。

応用

もらったスキルを入れる

zip や GitHub リポジトリの形で受け取った既製スキルも、置き場所はまったく同じ。

Terminalzip を受け取った場合
unzip ~/Downloads/pdf-report.zip -d ~/.claude/skills/

# SKILL.md が直下にある構造になっているか確認
ls ~/.claude/skills/pdf-report
# => SKILL.md  reference.md  scripts/
Terminalリポジトリの一部を使う場合
git clone https://github.com/anthropics/skills.git ~/src/skills
ln -s ~/src/skills/document-skills/pdf ~/.claude/skills/pdf
  • SKILL.md がフォルダ直下にあること。1 階層深いと認識されない。
  • シンボリックリンクで置いてもよい。Claude Code はリンク先の SKILL.md を読む。
  • 補助ファイル（reference.md、scripts/ など）は必要になったときだけ読まれるので、同じフォルダに入れておいてよい。
入れる前に中身を読む

スキル本文の !`...` はシェルコマンドとして実行され、allowed-tools は許可確認を省略させる。 他人のスキルは、この 2 つが何をしているか目視してから置く。

ルート B — プラグイン

マーケットプレイスから入れる

複数のスキルやエージェント、MCP サーバーがまとまった配布物はプラグインとして入れる。 デスクトップアプリならターミナルを使わず GUI で完結する。

GUI から

  • プロンプト欄の ＋ボタン → プラグイン：導入済みプラグインとそのスキルが並ぶ。
  • プラグインを追加 でブラウザが開き、公式マーケットプレイスを含む登録済みカタログから選べる。
  • プラグインを管理 で有効化・無効化・アンインストール。
  • スコープは ユーザー / プロジェクト / ローカル の 3 択。自分用ならユーザー。

コマンドから

プロンプト欄
# 1. カタログを登録する（公式は初回起動時に自動追加済み）
/plugin marketplace add anthropics/claude-plugins-community

# 2. 名前を指定して入れる
/plugin install commit-commands@claude-code-plugins

# 3. 「Run /reload-plugins to activate.」と出たときだけ実行
/reload-plugins

# 確認・停止
/plugin list
/plugin disable commit-commands@claude-code-plugins

プラグインのスキルは名前空間付きになる。commit-commands なら /commit-commands:commit のように呼ぶ。 /plugin だけで開くパネルには Discover / Installed / Marketplaces / Errors の 4 タブがあり、 導入前にコンテキスト消費量と追加される中身を確認できる。

信頼できる配布元だけ

プラグインは自分の権限で任意のコードを実行できる。マーケットプレイスを削除すると、 そこから入れたプラグインもまとめてアンインストールされる点も覚えておく。

ルート C — アカウント同期

Cowork・クラウドでも使えるようにする

デスクトップアプリの Cowork タブとクラウドセッション、ルーティンは、 ローカルの ~/.claude ではなく claude.ai アカウントの設定を見る。 そこで使いたいスキルは、サイドバーの カスタマイズ（Customize） から有効化する。

  • サイドバーの カスタマイズ でコネクタ・スキル・プラグインを一括管理。ここの設定がアカウント経由で同期される。
  • クラウドセッションでは、リポジトリにコミットした .claude/skills/ も読まれる。チーム共有ならこちらが確実。
  • ルーティンから /my-skill を呼んで「見つからない」と言われたら、まずここが原因。

アカウントで有効にしたスキルをローカルの通常セッションにも降ろしたい場合は、一度だけ非対話モードで同期する。

Terminal
CLAUDE_CODE_SYNC_SKILLS=1 claude -p "List the skills you have available"

# ~/.claude/skills/synced/ にダウンロードされる
# 以降の通常セッションでは /skills の「claude.ai sync」に並ぶ

同期スキルは名前が他のコマンドと衝突すると読み飛ばされ、ローカル側が優先される。 synced というフォルダ名は予約済みなので、自作スキルには使わない。

運用

無効化と削除

入れた経路消し方
個人・プロジェクトスキルのフォルダごと削除する（rm -rf ~/.claude/skills/<name>）。セッション中でも即座に一覧から消える
プラグイン/plugin uninstall <name>@<marketplace>、または ＋ボタン → プラグインを管理
アカウント同期カスタマイズ側でオフにする。フォルダだけ消しても次の同期で戻ってくる
組み込みスキル設定の disableBundledSkills、または skillOverrides で個別に "off"

消さずに「自動発動だけ止めたい」なら、frontmatter に disable-model-invocation: true を足す。 ファイルを触りたくなければ設定の skillOverrides に "user-invocable-only" を書く。

診断

効かないときに見る順番

症状よくある原因対処
/skills に出てこない パスの階層が違う／ skills フォルダを今セッション中に新設した <name>/SKILL.md の形か確認し、セッションを開き直す
自動で発動しない description が抽象的、または disable-model-invocation が立っている 「何をする＋いつ使う＋想定される言い回し」を description に足す
逆に発動しすぎる description が広すぎる 適用条件を絞る。paths でファイル種別に限定するのも有効
別のスキルが動く 同名衝突（個人がプロジェクトに勝つ） フォルダ名を変える。プラグイン側なら /plugin:name で明示する
ルーティン／Cowork で「見つからない」 ローカルの ~/.claude/skills/ にしか無い ルート C でアカウント側に登録する
プラグインのスキルが出ない キャッシュ不整合 rm -rf ~/.claude/plugins/cache → 再起動 → 入れ直し
description が途中で切れる 1,536 文字の上限 重要な用途を先頭に書く

まとめて確認したいときは /doctor。設定・プラグイン・環境の問題を一通り点検してくれる。
