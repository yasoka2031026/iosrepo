# LINEトーク整理アプリ構想（個人向け）

## 目的
LINEの全トーク履歴を対象に、NotebookLMのように以下を実現する個人用アプリを作る。
- 自動要約（期間・相手・トピック単位）
- 必要情報の検索・抽出（例: 日程、金額、住所、ToDo）
- 会話の文脈を保ったQ&A（「先週Aさんと決めた予定は？」など）

## 前提
- 利用ユーザーは自分1人
- ランニングコストは最小化
- UIはシンプルでダークテーマ

## 推奨アーキテクチャ（低コスト重視）

### 1. データ取り込み
- LINEのエクスポートテキストを手動インポート
- 添付ファイルは最初は対象外（Phase 2で対応）
- ローカルで前処理（発言者、日時、本文を正規化）

### 2. インデックス化
- 会話をチャンク化（例: 20〜50発言単位）
- メタデータ付与（相手名、期間、トークルーム、タグ）
- 埋め込みを作成してベクトルDBに保存
  - 第一候補: SQLite + sqlite-vss / LanceDB / Chroma（ローカル利用）

### 3. 検索 + 要約 + Q&A
- Retrieval-Augmented Generation (RAG)
- 低コスト運用案:
  - 通常: 軽量モデル（ローカルLLMまたは安価API）
  - 高品質が必要な時だけ上位モデルを手動切替
- 回答には根拠チャンク（どの会話から来たか）を必ず表示

### 4. UI/UX
- 画面構成を最小化:
  1. トーク一覧
  2. 検索/質問パネル
  3. 要約・抽出結果パネル
- ダークデザイン:
  - 背景: #0f1115
  - カード: #171a21
  - アクセント: #7aa2f7
  - 文字: #e5e9f0

## MVP（最初に作る範囲）
1. テキストインポート（1トークルーム）
2. 日付範囲で検索
3. 「要約して」「決定事項だけ」「ToDoだけ」質問テンプレ
4. 回答に根拠メッセージを紐づけ表示
5. ローカル保存（クラウド同期なし）

## 技術スタック案
- フロント: SwiftUI（iOS/macOSどちらか先行）
- ローカルDB: SQLite
- 埋め込み/検索: sqlite-vss または外部軽量ベクトルDB
- 推論:
  - Option A: ローカルLLM（ゼロ運用費、初期セットアップ重め）
  - Option B: API併用（初期が早い、従量課金）

## コスト最適化戦略
- 埋め込みは初回インポート時のみ作成（差分更新）
- 回答時は必要チャンクだけ取得して短文コンテキスト化
- 長い会話は段階要約（先に圧縮してから回答）
- 高価モデルは「最終回答時のみ」利用
- まずは1ユーザー前提でサーバーレス/ローカル完結

## セキュリティ・プライバシー
- 端末ローカル保存を基本
- API利用時は匿名化（人名・電話番号などのマスク）オプション
- 履歴の再インポート・完全削除をUIから可能に

## 開発ロードマップ（4週間例）
- Week 1: インポート・正規化・保存
- Week 2: ベクトル検索 + 基本Q&A
- Week 3: 要約テンプレとUI改善（ダークテーマ統一）
- Week 4: 精度調整・速度改善・個人運用最適化

## 次のアクション
- まずはMVPとして「1トークルームのインポート〜検索〜要約」までを実装する。
- 精度よりも、低コストで毎日使える操作感を優先する。
